- `1단계: 질문 분류(Intent Classification) 계층 추가`
- 지금은 키워드 매칭으로 테이블을 고르기 때문에, 키워드에 없으면 놓칩니다.
- LLM 기반 질문 분류를 RAG/도구 호출 앞 단계에 넣습니다.
- 예: "강경구 직급이랑 최근 성과" → [employees, performance_records]
- 예: "IFRS S2 전환 준비도" → [disclosures]
- 예: "회의실 예약" → [none] (등록된 도메인 아님)
- 키워드 매칭은 빠른 1차 필터로 두고, LLM 분류는 보완/보정 역할을 해서,
  키워드에 없는 질문도 올바른 테이블에 매핑되게 합니다.
- 분류 결과를 메타데이터로 남기면 "왜 이 테이블이 선택됐는지"가 추적 가능합니다.
- `2단계: 도구 선택을 모델에 위임 (Tool Calling 자율성 강화)`
- 지금은 시스템 프롬프트에 "이런 질문이면 이 도구를 써라" 규칙을 나열합니다.
- 도구 수가 늘어나면 규칙이 비대해지고, 경계가 모호한 질문에서 실수가 잦아집니다.
- 모든 도구 설명(description)을 충분히 풍부하게 적어 두면,
- 모델이 질문을 보고 스스로 "이 질문에는 get_employee_info + get_employee_performance가 필요하다"고 판단해 호출합니다.
- 규칙 나열 대신 "필요한 도구를 직접 판단해서 호출하세요" 라는 지시를 주면,
- 등록되지 않은 새로운 유형도 도구 설명만 잘 돼 있으면 자연스럽게 선택됩니다.
- 그러면 "규칙에 등록되지 않은 질문" 문제가 줄어듭니다.
- `3단계: RAG 검색에 테이블 라우터 추가`
  지금은 키워드별로 disclosure/competency_anchors/employees를 각각 따로 검색해서 합칩니다.
- 통합 벡터 검색: 모든 테이블의 임베딩을 하나의 벡터 인덱스에 넣되, table 메타데이터를 필터로 사용.
- 질문에 맞는 문서를 테이블 구분 없이 유사도 순으로 뽑되, 결과에 "이건 employees, 이건 disclosures" 태그가 붙는 방식.
- 키워드 없어도 의미 기반으로 맞는 테이블의 문서가 자동으로 올라옵니다.
- 하이브리드: 키워드 기반(빠르고 확정적) + 의미 기반(유연하고 키워드 누락 커버)
두 가지를 합쳐서, 키워드에 있으면 그 테이블 우선, 없으면 의미 검색으로 보완.
- `4단계: 출처 명시 (답변 레벨)`
- 인라인 출처: 답변 문장마다 [출처: employees], [출처: performance_records] 같은 태그를 붙이게 프롬프트로 지시.
- 예: "강경구는 개발·IT 부서 팀장입니다 [employees]. 2025-Q4 보고서에서 프로젝트 리드 역할을 수행했습니다 [performance_records]."
- 사용 도구/테이블 요약: 답변 하단에 "사용한 데이터: employees, performance_records" 라벨을 자동으로 표시.
- 참고 문서 그룹핑: 프론트 "참고 문서" 섹션을 테이블별로 나눠서 표시 → "직원 정보 2건 / 성과 3건 / 공시 1건".
- `5단계: Out-of-Scope 명시`
등록된 테이블/도메인으로 답할 수 없는 질문을 명확히 구분합니다.
- 1단계 분류에서 [none]이 나오면:
- "이 질문은 현재 등록된 데이터(직원·성과·공시·역량)로는 답변할 수 없습니다. 일반 지식으로만 답변합니다."
- 또는 "현재 시스템에서 지원하지 않는 질문 유형입니다."
- RAG 검색 결과 0건 + 도구 호출 0건인 경우에도 같은 메시지를 자동 표시.
- `6단계: 감사 로그 (추적/디버깅)`
- 매 질의마다 "분류 결과 → 선택된 테이블/도구 → RAG 검색 건수 → 도구 호출 내역 → 최종 답변"을 한 줄 로그로 남겨,
- 나중에 "왜 이 질문에 이 답이 나왔는지"를 역추적 가능하게 합니다.
